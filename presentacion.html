01 — Introducción

¿Qué es PawMatch?

PawMatch es una plataforma web que permite a los dueños de mascotas registrar a sus animales, explorar otras mascotas cercanas, enviar likes y chatear en tiempo real cuando hay un match mutuo — inspirada en el modelo de Tinder, pero diseñada para el mundo animal.

💡

Problema que resuelve

Los dueños no tienen una forma sencilla de encontrar compañeros de juego o parejas reproductivas para sus mascotas en su área local.

🎯

Propuesta de valor

Perfil por mascota, sistema de matches, chat exclusivo por match y un flujo intuitivo similar a las apps de citas modernas.

🌐

Tipo de aplicación

Web full-stack: API REST con Django + SPA en React. Comunicación en tiempo real mediante Django Channels (WebSocket).

🔒

Enfoque en seguridad

Autenticación por token con expiración absoluta e inactividad, throttling, headers HTTP de seguridad y bitácora de eventos.

02 — Objetivos

¿Qué busca lograr?

Objetivos generales y específicos del proyecto integrador.

1

Registro y autenticación segura: Permitir a los usuarios registrarse, iniciar sesión y mantener su sesión de forma segura usando tokens con expiración y control de inactividad.

2

Gestión de mascotas: Que cada dueño pueda registrar una o más mascotas con foto, nombre, especie, raza y ubicación geográfica.

3

Sistema de matches: Implementar un flujo de likes entre mascotas que genere un match cuando el interés es mutuo, bloqueando la relación si un usuario la rechaza.

4

Chat en tiempo real: Habilitar un canal de mensajería WebSocket exclusivo para cada match aceptado, con indicador de escritura en vivo.

5

Seguridad alineada a estándares: Aplicar las buenas prácticas de la Guía de Desarrollo Seguro, cubriendo OWASP Top 10, headers HTTP, rate limiting e IDOR.

6

Reportes entre usuarios: Permitir reportar contenido o usuarios inapropiados con rate limiting para evitar abuso (máx. 10 reportes/hora).

04 — Usuarios

Tipos de usuario

El sistema tiene un único tipo de usuario registrado: el dueño de mascota.

Rol Descripción Acciones principales
🐾 Dueño (usuario) Persona registrada con una o más mascotas Registrar mascota, dar likes, chatear, ver matches, reportar, editar perfil
👤 Anónimo Visitante no autenticado Ver página de login y registro únicamente (máx. 200 req/hora)
📱

Dueños de mascotas

Único tipo de usuario registrado. Usan la app para conectar sus mascotas con otras cerca de su ubicación.

🐶

Mascotas (entidad)

Cada dueño puede tener N mascotas. Las mascotas son las que hacen likes y matches, no los dueños directamente.

08 — Módulos

Módulos del backend

El proyecto está organizado en cuatro aplicaciones Django, cada una con responsabilidad única.

🔐

auth_app — Autenticación y sesiones

Registro, login, logout, Google OAuth2, tokens Bearer con expiración absoluta (7 días) e inactividad (5 min), bitácora de eventos.

POST /register POST /login POST /logout TokenActividad BitacoraEvento OAuth2
🐾

pets_app — Gestión de mascotas

CRUD de mascotas con subida de fotos, validación de tipo MIME y magic bytes, geolocalización y filtro por distancia.

GET /pets/ POST /pets/ GET /pets/my-pets/ Magic bytes validation 5 MB limit
💘

matches_app — Sistema de matches

Likes entre mascotas, generación automática de match mutuo, rechazo, listado de matches aceptados, reportes con rate limit.

POST /matches/like/ GET /matches/ POST /reportes/ ReporteRateThrottle IDOR protection
💬

chat_app — Mensajería en tiempo real

WebSocket por sala de match, autenticación en el primer mensaje, indicador de escritura, historial paginado de mensajes.

GET /mensajes/?match_id= WS /ws/chat/<id>/ First-message auth Typing indicator

09 — Seguridad

Medidas de seguridad implementadas

Alineadas a la Guía de Desarrollo Seguro y OWASP Top 10. Se cubren 45 de 47 casos de prueba del plan.

🔑
Token + expiración dobleExpiración absoluta a 7 días y cierre por inactividad a los 5 min sin actividad.
🚦
Rate LimitingLogin: 5/min · Registro: 3/min · Reportes: 10/hr · Anón: 200/hr · Auth: 2000/hr.
🛡️
Headers HTTPCSP, Referrer-Policy, Permissions-Policy, X-Frame-Options: DENY, X-Content-Type-Options.
🔍
Validación de archivosExtensión + tipo MIME + magic bytes. Rechaza archivos renombrados con extensión falsa.
🚫
Protección IDORCada usuario solo accede a sus propias mascotas y mensajes. Estado de match es read-only.
📋
Bitácora de auditoría13 tipos de eventos: login, logout, mascota, match, mensaje, reporte, acceso denegado…
🔐
CORS estrictoSolo orígenes explícitamente permitidos. No se usa wildcard *.
🌐
HSTS + HTTPSEn producción (DEBUG=False): HSTS 1 año, SSL redirect, cookies seguras con SameSite Strict.
🕵️
Sin enumeración de usuariosLogin con email inexistente devuelve el mismo código 400 que credenciales incorrectas.
📡
Auth WebSocketEl token se valida en el primer mensaje WS. Sin autenticación en 5 seg → cierre con código 4001.
🔒
Secrets en .envSECRET_KEY, DATABASE_PASSWORD y credenciales de OAuth2 fuera del código fuente.
📵
Inactividad frontendTimer de 5 min en React: cierra sesión y redirige a /session-expired si el usuario no interactúa.
✅
